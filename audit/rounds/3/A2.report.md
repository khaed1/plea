# Audit report

> PLEA security audit, round 3, area A2: Letters and the launch: Letterbox, PleaLaunch, PLEA, PleaDistributor. PLEA is a sell-gated meme token on Uniswap v4 paired with IMD: anyone buys, selling needs a plea judged by a 30-seat IdentityMD oracle panel, approved pleas score season points for IMD and PLEA prizes, and every trade pays cashback in staked IMD through imd/acc's Stacker. Solidity 0.8.26, Foundry (cancun, via-IR), a Uniswap v4 hook, IdentityMD Intake v2 callbacks. ## Findings

### 1. Low: Letterbox._appeal: fees that pass the original-amount exception can exceed the writer's balance, so a retried APPEAL letter dies in PLEA's ERC20InsufficientBalance instead of FeeTooHigh

`src/Letterbox.sol:348`

```
        if (maxFeePlea * BPS > bal * MAX_FEE_SHARE_BPS && maxFeePlea > originalAmount) {
            revert FeeTooHigh(maxFeePlea, bal);
        }
        plea.courtTake(writer, amount + maxFeePlea);
```

The R1-A2-3 exception admits an appeal's fees above 10% of the balance whenever they are at most the original plea's amount, but nothing checks that the escrow plus the fees still fit the balance (amount + maxFeePlea <= bal) before courtTake pulls them. On the mainnet fee path an appeal letter's fees are 1.1 IMD x 1.1 = 1.21 IMD worth of PLEA. A writer whose whole position is worth about 2.4-3.6 IMD can plead 50% at the gate, be denied, appeal by letter (escrow B/2 + 1.21 IMD worth fits), get no verdict, and then the retry the design promises computes amount = half of the fee-shrunken balance while the fees still pass the exception; courtTake then reverts inside the token. The Letterbox never reaches its own error, so an explorer user sees a raw ERC-20 error with no hint. Nothing moves and the writer can still appeal at the gate with IMD, so this is a confusing refusal on a tiny position, not a loss; invariant 15 (whoever could plead by letter can appeal by letter) is untouched because a letter needs about 8.25 IMD worth on mainnet. The site's plead(amount, text) has the same ordering (an amount above the balance reaches courtTake before the gate's AmountTooLarge). Fix: after the amount is final, `if (amount + maxFeePlea > bal) revert FeeTooHigh(maxFeePlea, bal);` in _appeal (and optionally the same guard in _plead). Verified: the specialist's proof fails on this tree with 'raw ERC-20 error instead of FeeTooHigh' (merged from audit_economics fefde265).

**Reproduction**

Mainnet fee path (Fixture with oracleFeeToken() = the pool IMD). bob buys 50 IMD of PLEA, alice buys 3.3 IMD; bob holds a week keeping the Cabal alive. alice: gate.submitSell(balance/2, text); the panel answers 0 -> Denied. alice sends the letter 'APPEAL The rent is due on Monday; I keep the other half.' -> accepted (fees 1.21 IMD worth sold from her PLEA). skip 21 minutes with no verdict. alice sends 'APPEAL Still Monday, still the rent; I keep the other half.' Expected: the appeal is re-sent, or the Letterbox reverts FeeTooHigh(maxFeePlea, balance). Actual: revert selector 0xe450d38c ERC20InsufficientBalance(alice, balance, amount + maxFeePlea) from PLEA.courtTake, because maxFeePlea (1.21 IMD worth) <= the original amount lets the check at line 348 pass while amount (half the shrunken balance) + maxFeePlea > balance. `forge test --match-path test/scratch/Proof_fefde26553ea.t.sol` fails with 'raw ERC-20 error instead of FeeTooHigh' (run on this commit).

pragma solidity 0.8.26;

import {Fixture} from "../utils/Fixture.sol";
import {MockIMD} from "../utils/Mocks.sol";
import {IERC20Errors} from "@openzeppelin/contracts/interfaces/draft-IERC6093.sol";
import {Letterbox} from "../../src/Letterbox.sol";
import {CabalGate} from "../../src/CabalGate.sol";

/// Mainnet fee path: a writer whose whole position is worth 2.4-3.6 IMD pleads 50% at the gate,
/// is denied, appeals by letter (works: the fees, 1.21 IMD worth of PLEA, are under the original
/// amount), the panel never answers, and the retry letter reverts with the token's
/// ERC20InsufficientBalance instead of the Letterbox's FeeTooHigh: the fee exception compares the
/// fees with the original amount, but the escrow plus the fees no longer fit the shrunken balance.
contract AppealRetryOpaqueRevertTest is Fixture {
    function oracleFeeToken() internal view override returns (MockIMD) {
        return imd;
    }

    function test_appealRetryByLetterRevertsWithARawTokenError() public {
        buy(bob, 50e18);
        buy(alice, 3.3e18);
        holdAWeek(bob); // alice holds a week: 50% of the balance scores 3 + 7 + 13 + 5 = 28, need 43
        uint256 bal = plea.balanceOf(alice);
        uint256 price = hook.latestPrice();
        uint256 worth = bal * price / 2 ** 96;
        assertGt(worth, 2.42e18, "position worth over 2.42 IMD");
        assertLt(worth, 3.57e18, "position worth under 3.57 IMD");

        uint256 id = plead(alice, bal / 2, "Half for the rent; the rest stays with me through the winter.");
        assertTrue(answer(id, 0), "denied");

        vm.prank(alice);
        (bool ok,) = address(letterbox).call(bytes("APPEAL The rent is due on Monday; I keep the other half."));
        assertTrue(ok, "the first appeal letter goes through");
        uint256 a = gate.lastPleaOf(alice);
        assertTrue(gate.getPlea(a).isAppeal);

        skip(21 minutes); // no verdict: the appeal is stale and may be sent again (fees paid again)

        (uint256 feeImd, uint256 maxFeePlea) = letterbox.feesFor(true);
        assertEq(feeImd, 1.1e18);
        vm.prank(alice);
        bytes memory ret;
        (ok, ret) = address(letterbox).call(bytes("APPEAL Still Monday, still the rent; I keep the other half."));
        assertTrue(maxFeePlea <= gate.getPlea(id).amount, "the fee exception applied: fees under the original amount");
        assertGt(maxFeePlea * 10_000, plea.balanceOf(alice) * 1_000, "and the fees exceed 10% of the balance");
        // Expected: the Letterbox's own FeeTooHigh (or the appeal going through); actual on this
        // code: the token's ERC20InsufficientBalance from courtTake.
        if (!ok) {
            assertTrue(
                bytes4(ret) != IERC20Errors.ERC20InsufficientBalance.selector, "raw ERC-20 error instead of FeeTooHigh"
            );
            assertEq(bytes4(ret), Letterbox.FeeTooHigh.selector, "the Letterbox should refuse the fees by name");

### 2. Low: Letterbox.status() reports a stale Pending letter as PENDING with no settle hint although no verdict can arrive and anyone can settle it

`src/Letterbox.sol:535`

```
        if (s == CabalGate.Status.Pending) {
            return string.concat(
                head, unicode"PENDING · asked ", Strings.toString((block.timestamp - p.submittedAt) / 60), "m ago"
            );
        }
```

Display only, the same class as the fixed R1-A2-4. Once PENDING_EXPIRY (20 minutes) has passed, or the Intake completed the request without a verdict, the gate refuses any late verdict (onOracleResult reverts TooLate) and the escrow is settleable by anyone (_settleable is true; settle calls gate.expire and returns the PLEA and the 0.25 IMD tip). status() still returns 'Plea #N · PENDING · asked Nm ago' without _escrowNote, so a writer reading the explorer view waits for a verdict that cannot come while their 15% and tip sit in the Letterbox until they or a stranger call settle. No funds are at risk. Fix: in the Pending branch, when _settleable(id) is true return the NO VERDICT line with _escrowNote(id), or append '· call settle to get your PLEA back'. (Merged from audit_permissions f569a419; reproduced with test/scratch/JudgeA2.t.sol test_stalePendingStatusHasNoSettleHint on this commit.)

**Reproduction**

Nobody answers. skip(21 minutes). Expected: status(alice) says the plea got no verdict and that settle returns the PLEA and tip, as the LAPSED and NO VERDICT lines do. ### 3. Info: The fixed 95%-of-checkpoint delivery minimum has no override: an approved auto-sell plea cannot be sold at all while spot sits more than 5% under the hour's checkpoint, and that checkpoint is whatever

`src/Letterbox.sol:390`

```
        uint256 minOut = FullMath.mulDiv(amount, _price(), FixedPoint96.Q96) * MIN_OUT_BPS / BPS;
```

Two consequences of the agreed number, not a defect in the Letterbox (merged from audit_permissions e57cf4ba and audit_economics 6d7bc542). (1) Liveness: _deliver fixes minOut at 95% of the hourly checkpoint value (_price() = PleaHook.latestPrice()) and CabalGate.executeSell reverts UseLetterbox for any AUTO_SELL plea, so a writer whose approval arrives while the pool price has fallen more than 5% below the hour's first-trade checkpoint (several approved sales earlier in the same hour on a thin pool) has no way to take the market: deliver and a SELL letter revert SlippageExceeded, the 7-minute window lapses, the escrow comes back through settle and the 4-hour lapse cooldown runs from the verdict. Not attacker-triggerable while the Cabal lives (only approved sellers move the price down) and the points still count. (2) What the floor guarantees: the checkpoint is the pre-trade spot of the current hour's first trade (THREAT-MODEL section 3, 'one trade per hour sets no reference'), so when a letter's 7-minute window spans an hour boundary and no trade has happened in the new hour, a dust buy by anyone (the runner included) makes the current spot the checkpoint, and the 95% then protects the writer only against in-swap slippage, not against a market fall since the plea's own snapshot. Suggested: document both in THREAT-MODEL section 3 / README 'Auto-sell' ('at least 95% of the price the current hour's first trade found'), or let a SELL letter carry its own minimum.

**Reproduction**

Code path: Letterbox._deliver line 390 computes minOut from latestPrice(); CabalGate._sell line 601 reverts SlippageExceeded(out, minOut) when out < minOut; CabalGate.executeSell line 569 reverts UseLetterbox when FLAG_AUTO_SELL is set, and every Letterbox plea carries that flag (_onlyLetterbox's BadFlags). Mechanism test on this commit: test/scratch/JudgeA2.t.sol::test_deliverHasNoWayOutWhenSpotIsUnderTheCheckpointBand: alice's approved 15% letter; with the hook's latestPrice() mocked 10% above the market, keeper.deliver(id) and alice's SELL letter revert and alice's gate.executeSell(0) reverts UseLetterbox; with the real checkpoint the same deliver pays out. Hour-boundary note: PleaHook._checkpoint (line 1004) writes ring[hour] with the pre-trade sqrtPrice only on the hour's first swap, so a dust buy in a trade-free hour sets the reference deliver reads.

### 5. Info: PleaLaunch.seed writes `opened` but never reads it: a second seed is refused by the hook, not by the launch contract

`src/PleaLaunch.sol:190`

```
        opened = true;
        IPleaHook(hook).seed();
        IGate(gate).begin();
```

seed() sets the public flag `opened` and nothing in PleaLaunch checks it: a second call writes it again and reaches IPleaHook(hook).seed(), which reverts AlreadySeeded (CabalGate.begin would also revert AlreadyBegun). Invariant 17 ('seed opens trading once') holds today through the hook, but the once-guard lives in another contract than the one documented to open trading, and the flag is dead storage written in the launch-opening transaction. Style/gas only. Fix: `if (opened) revert AlreadyOpened();` before the write, or drop the flag. (Merged from audit_permissions d3eac91f and audit_flow 6748d978.)

**Reproduction**
