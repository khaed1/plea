## Findings

### 1. Low: Plea and objection text filters accept the Mongolian free variation selectors U+180B-180D and U+180F although invariant 2 refuses every variation selector

`src/CabalGate.sol:871`

```
                || cp - 0x890 <= 1 || cp == 0x8e2 || cp == 0x180e || cp - 0x200b <= 4 || cp - 0x2028 <= 6
```

THREAT-MODEL invariant 2 (round 7, R7-A1-2), README 'Plea text rules' and OBJECTIONS.md say a plea or objection holds no variation selector. Unicode's Variation_Selector property (PropList.txt) has three ranges: U+180B-180D and U+180F (Mongolian free variation selectors FVS1-FVS4), U+FE00-FE0F and U+E0100-E01EF. CabalGate._refused refuses only the last two (cp - 0xfe00 <= 15 and the cp >> 12 == 0xe0 block) plus U+180E, which is Cf; the four Mongolian selectors are general category Mn and Default_Ignorable_Code_Point, so the R7-A1-2 Cf sweep did not catch them and they render invisibly outside Mongolian script. Tribunal._refused (src/Tribunal.sol:522) is the verbatim copy and has the same gap. Impact: invisible characters can still reach the judges' question and the explorer views, the display and smuggling concern R7-A1-2 set out to close; no value moves and the gate's logic is unchanged, so Low (the literal invariant breach would read High, but the round-7 judge rated the Cf gap Info and this is the same class). Merged from the permissions and economics specialists, who found the same four code points. Fix: add `|| cp - 0x180b <= 2 || cp == 0x180f` (or `cp - 0x180b <= 4`, which keeps U+180E refused) to both _refused copies, keeping them identical; CabalGate has 641 bytes of room. Alternatively reword invariant 2 and the README to list only the refused ranges.

**Reproduction**

Call CabalGate.submitSell(amount, text) or Tribunal.object(pleaId, text) with text whose bytes are 0x61 E1A08B 0x62 ('a', U+180B, 'b'); likewise E1A08C, E1A08D, E1A08F. Expected (invariant 2, as for 0x61 EFB88F 0x62 with U+FE0F and for E1A08E with U+180E): revert BadPleaText / BadObjectionText. Actual: _validateText accepts the text and the plea is paid for and sent to the panel with the invisible selector inside. Reproduced: the proof's harness inherits CabalGate and exposes _validateText; test_mongolianFreeVariationSelectorsAreRefused fails on this commit with 'next call did not revert as expected' and test_fe0fIsRefused (the control) passes; both specialists' proofs fail the same way here.

### 2. Info: R7-A1-1 weighted mean: one wei over a buy record whose facts beat received PLEA's still costs one fact point (floor); the regression test only covers the direction where the floor is invisible

`src/CabalGate.sol:285`

```
            facts = (heldPlea * facts + (amount - heldPlea) * (_heldPoints(startedAt) + 10)) / amount;
```

The round-7 fix scores a plea larger than the buy record as the PLEA-weighted mean of the record's hold + profit points and the received PLEA's (hold since startedAt + 10), rounded down. The floor is the agreed rule (THREAT-MODEL invariant 3 and section 3), so no agreed number changes and this is not a defect in the code. But the rounding is asymmetric and test/AuditRevision.t.sol::test_oneWeiOverTheBuyRecordKeepsTheRecordsFacts only exercises the case where the received PLEA's facts (12) exceed the record's (6): there floor((6H + 12) / (H + 1)) = 6 and the name's property holds. In the opposite and common case, a long holder at a loss (7 + 13 = 20) whose received-PLEA facts are 7 + 10 = 17, one wei over the record gives floor((20H + 17) / (H + 1)) = 19 for any H >= 3 wei: one fact point lost and the need one higher although the exact mean is 19.99999. The seller controls the amount and no value moves, so informational: the test's name promises a property the code has in one direction only, and the FINDINGS/THREAT-MODEL phrase 'one wei over the record no longer rescores the whole plea' is true while one point still moves. If the owner wants the literal property, round to nearest or floor only the uncovered part; otherwise document the floor's direction and extend the test. Confirmed from the math specialist's report.
