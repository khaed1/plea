## Findings

### 1. Info: Deploy.s.sol reads Seasons' seat NFT with envOr (defaults to address(0)) and omits SEAT from its documented env list, so a rehearsal silently deploys a Seasons without the 1.2x seat multiplier

`script/Deploy.s.sol:41`

```
                abi.encode(address(plea), address(gate), vm.envAddress("IMD"), vm.envOr("SEAT", address(0)))
```

Merged from the economics and permissions specialists (both reported the same line). The script's NatSpec (lines 18-19) lists the variables it needs: OWNER, INTAKE, ORACLE_ASSET, IMD, ORACLE_SIGNER, SEASON, DEADMAN, POOL_MANAGER, STACKER, CREDIT_GAS, START, MINT_ORACLE_FEE. SEAT is not among them, and Seasons' fourth constructor argument is the only address the script reads with vm.envOr, defaulting to address(0); every other address uses vm.envAddress and reverts when missing. A local or fork rehearsal run with exactly the documented variables therefore deploys a Seasons whose immutable seat is zero: Seasons.holdsSeat (src/Seasons.sol:139-144) returns false for every wallet because of its `seat == address(0)` short-circuit, so THREAT-MODEL invariant 7's seat multiplier (45 -> 54) never applies in that rehearsal, with no error, log or test flagging the divergence from launch.json, whose fourth Seasons word is the identity.md NFT 0x0000ec93127baa929e58e97dd0095a2bfb38ec1d (confirmed on chain 1: 5,231 bytes of code, name() = "identity.md", supportsInterface(ERC-721) = true). Impact is limited to local rehearsals: THREAT-MODEL section 3 says script/*.s.sol are local-simulation helpers and the real launch is the factory's atomic launch.json transaction, which test/LaunchManifest.t.sol checks against the SEAT constant (test_launchJsonAddressWordsAreTheTestedAddressesInAValidCase, green on this commit). Severity Info per the scale (scripts/tests). Fix: read it with vm.envAddress("SEAT") and add SEAT to the header's env list (or document in the header that an unset SEAT means no multiplier).

**Reproduction**

On this commit, from the repository root, with the header's twelve variables set to the mainnet launch.json values and SEAT unset: `env -u SEAT OWNER=0x5BF3597216f9019Cf10CF680783289Efc8639Bf0 INTAKE=0xa43e6f75ee006411f79ac1c84120606c2330de82 ORACLE_ASSET=0xd34a99bc0f67ae1bbd63c660e6d0b0dd03e263b7 IMD=0xd34a99bc0f67ae1bbd63c660e6d0b0dd03e263b7 ORACLE_SIGNER=0x5598Aa9146215Bc13eb26f2c692Ad1461Fd32982 SEASON=1296000 DEADMAN=118800 POOL_MANAGER=0x000000000004444c5dc75cB358380D2e3dE08A90 STACKER=0x06909f672301f28a810f78cfe7a754851269f4f0 CREDIT_GAS=400000 START=1795532400 MINT_ORACLE_FEE=false forge script script/Deploy.s.sol`. Expected (by analogy with every other address argument and with launch.json, where the seat is a required fourth word): the script refuses to run without SEAT, as vm.envAddress would. Actual: 'Script ran successfully', seven contracts logged (PLEA, CabalGate, Seasons, PleaDistributor, PleaLaunch, Letterbox, Tribunal), and the Seasons it deployed was constructed with seat_ = address(0) (src/Seasons.sol:106), so Seasons.seat() == 0x0000000000000000000000000000000000000000 and holdsSeat(w) / pointsFor(w, 45) return false / 45 for a wallet holding the identity.md NFT instead of true / 54.
