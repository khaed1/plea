## Findings

### 1. Low: A Letterbox constructor refusal (the Sepolia mint flag or a foreign oracle asset on chain id 1) makes deployLetterbox revert forever; no on-chain guard or rehearsal catches it before the launch lands

`src/PleaLaunch.sol:138`

```
        if (deployed == address(0)) revert LetterboxDeployFailed();
```

The Letterbox's settings are checked only inside its own constructor (MintOnMainnet, OracleAssetNotImd, MintWithPoolImd, OracleAssetMismatch; src/Letterbox.sol lines 174-182), which runs after the launch, inside PleaLaunch.deployLetterbox. letterboxCodeHash, oracleAsset and mintOracleFee are immutable, the Letterbox takes no constructor arguments, and PLEA.setLetterbox is one-shot through the launcher, so a manifest whose Letterbox settings the constructor refuses launches the five contracts normally, passes IMD's rehearsal on a bare EVM with chain id 1 (the Letterbox is not in the manifest), passes seed()'s chain-1 guard (it checks only SEASON and DEADMAN) and opens trading; every later deployLetterbox(creationCode) then reverts with the opaque LetterboxDeployFailed (the raw create2 swallows the constructor's reason), now and forever. The result is a live launch with trading, the gate and the Tribunal but no letters, no site auto-sell box (plead / appealAuto) and no runner delivery: the gate's submitFor / appealFor / executeSellFor all revert NotLetterbox for good. The concrete trigger is the very word this commit's launch.json carries as PleaLaunch's 11th argument (mintOracleFee = 1) reused on chain id 1; an oracle asset other than the pool IMD with the flag off is the same irreversibility. R2-A2-1 (Low, fixed) added these constructor guards so a mismatched manifest cannot deploy a dead Letterbox; the refusal now happens after the point of no return instead. Operator error is required (the mainnet branch carries the right settings), so this is a launch-configuration hazard, not a logic bug: Low under THREAT-MODEL section 4 (a missing check with no impact today). Minimal fix without changing any agreed number: have seed()'s chain-1 branch (src/PleaLaunch.sol line 187) also refuse mintOracleFee and oracleAsset != imd, so a mis-set mainnet manifest is caught before trading opens and the launch can be redone; and bubble the constructor's revert data out of deployLetterbox / deployTribunal / deployHook (returndatacopy + revert) instead of the bare LetterboxDeployFailed, so the cause is visible. README step 1 could say that a refused constructor is permanent.

**Reproduction**

Reproduced with the flow specialist's test, copied to test/scratch/Proof_055091b5d7d0.t.sol and run with forge test --match-path (passes as a demonstration on this tree). vm.chainId(1); deploy PLEA(owner), CabalGate(plea, intake, oracleAsset = a token other than the pool IMD, imd, signer, 15 days, 33 hours), Seasons, PleaDistributor, then PleaLaunch with mintOracleFee = true and letterboxCodeHash = keccak256(type(Letterbox).creationCode). Expected (README 'Anyone calls PleaLaunch.deployLetterbox(creationCode) once'): either the launch is refused or deployLetterbox succeeds. Actual: the five-contract launch succeeds (plea.launcher() == launch), launch.deployLetterbox(creationCode) reverts LetterboxDeployFailed() (the inner MintOnMainnet() is hidden) on the first and on every later call, plea.letterbox() stays zero, and gate.executeSellFor(1, 0) reverts NotLetterbox(). With a fix in seed() (refusing mintOracleFee on chain id 1) the launch would refuse to open trading instead; with the revert data bubbled, the first call would show MintOnMainnet().

### 2. Info: README still states the letter minimum as 'whose 15% is under 1,000 PLEA' after the run-8 move to 20%

`README.md:92`

```
- **Fees are paid in PLEA, in the letter's own transaction.** The gate sells just enough of your PLEA, through the hook with the normal 2.0% fee and your own 0.5% cashback, for exactly the IMD needed: the 0.5 IMD oracle fee, a **0.25 IMD runner tip** and, for an appeal, the 0.35 IMD wall share. That is all a letter ever costs: **letters pay no auto-sell fee**, and a writer who sends `SELL` gets the tip back. It may spend at most the hourly snapshot value **+10%**; unspent PLEA comes straight back. A letter whose fees would take more than 10% of your PLEA, or whose 15% is under 1,000 PLEA, is refused (an appeal's fees may instead go up to the original plea's amount, with the same 10% slack, so whoever could plead by letter can appeal by letter unless the hourly price fell by more than about a tenth since the letter). On Sepolia the oracle fee token is a separate test token, so the Letterbox mints that 0.5 instead of buying it.
```

Run 8 moved the letter share to 20% (src/Letterbox.sol line 111: LETTER_SHARE_BPS = 2_000; README line 85, the Letterbox NatSpec, THREAT-MODEL invariant 15 and the launch.json notes all say 20%). The fee bullet on README line 92 still describes the LetterTooSmall rule as 'whose 15% is under 1,000 PLEA', i.e. a refusal under a 6,667 PLEA balance, while the code (src/Letterbox.sol lines 296-298: amount = bal * 2_000 / 10_000, refused under MIN_LETTER = 1_000e18) refuses under 5,000 PLEA. Reported by the economics, math and flow specialists; merged here. Documentation only: the agreed number in the code is unchanged and the 0.70 IMD floor dominates this minimum at any realistic price. Fix: '20%' on README line 92 (the appeal margin sentence in the same bullet, derived for 15% letters, is still true but no longer tight).

**Reproduction**

Compare README.md line 92 ('or whose 15% is under 1,000 PLEA, is refused') with src/Letterbox.sol lines 111 and 296-298. A writer holding 5,500 PLEA worth at least 8.25 IMD at the snapshot sends a letter: 20% = 1,100 PLEA >= MIN_LETTER, so the Letterbox accepts it (status Pending); the README sentence predicts LetterTooSmall (15% = 825 < 1,000). Expected: the README states the 20% rule; actual: it states 15%.
