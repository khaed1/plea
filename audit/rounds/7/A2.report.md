### 2. Info: Letterbox NatSpec on the appeal fee exception still carries the 15%-letter tolerance ('about a tenth'); with LETTER_SHARE_BPS = 2,000 the snapshot may fall about 14% on Sepolia and about a third on ma

`src/Letterbox.sol:357`

```
        // fell by more than about a tenth since the letter.
```

The comment above the FeeTooHigh exception in _appeal (lines 353-357) describes the run-7 figure for a 15% letter. The exception is `maxFeePlea * BPS > originalAmount * FEE_CAP_BPS` (line 358), and originalAmount is now 20% of the balance. Mainnet fee path (oracle fee bought): the smallest letter the 10% rule admits is a balance worth 8.25 IMD at the letter's snapshot P0 (fees 0.75 IMD x 1.1 = 0.825 IMD), so the original plea is worth 1.65 IMD; an appeal's fees are 1.1 IMD x 1.1 = 1.21 IMD at the appeal's snapshot P1, and the exception admits them while 1.21 / P1 <= 1.1 x 1.65 / P0, i.e. P1 >= 0.667 P0: a fall of up to a third. Sepolia (fee minted): the smallest letter is the 0.70 IMD floor (balance worth 3.5 IMD), appeal fees (0.25 + 0.35) x 1.1 = 0.66 IMD; 0.66 / P1 <= 0.77 / P0 gives P1 >= 0.857 P0: about 14%. With the old 15% letter the mainnet bound was 1.21 / P1 <= 1.1 x 1.2375 / P0, i.e. P1 >= 0.889 P0, the 'tenth' the comment and FINDINGS R4-A2-1 still state. README line 92 already gives 14% / about a third. The code is correct and matches README; only the comment is stale, so no agreed number changes. Fix: reword the comment to README's figures (or drop the fraction and point to README).

**Reproduction**

Documentation only; the figures follow from the code's own constants (LETTER_SHARE_BPS 2,000, FEE_CAP_BPS 11,000, MAX_FEE_SHARE_BPS 1,000, TIP 0.25e18, APPEAL_FEE 0.35e18, ORACLE_FEE 0.5e18, MIN_SALE_VALUE 0.7e18) and line 358. Concrete case, mainnet path: a writer whose balance is worth 8.25 IMD at snapshot P0 sends a letter (fees 0.825 IMD, exactly the 10% rule); it is denied; the hourly snapshot falls 25% (P1 = 0.75 P0); the writer sends an APPEAL letter: maxFeePlea = 1.21 / (0.75 P0) = 1.613 / P0 PLEA against originalAmount x 1.1 = 1.815 / P0 PLEA, so line 358 admits it and the appeal goes through. Expected per the comment: FeeTooHigh after a fall over a tenth. Actual: the appeal is accepted, consistent with README. Checked against test/AuditRound1.t.sol test_aSmallWriterCanAppealByLetterAfterThePriceFell (mainnet path, falls of 3-10% accepted) which is consistent with both figures and does not pin the bound.

### 3. Info: MIN_SALE_VALUE NatSpec says the 0.35 IMD auto-sell fee never exceeds half a sale, but a site plea worth 0.70 IMD at the snapshot sells for about 0.686 IMD after the hook's 2% fees, and for as little a

`src/Letterbox.sol:120`

```
    /// @dev A plea must be worth at least this at the snapshot (letters too), so the fee never
    /// exceeds half a sale and a letter's fees stay small next to it.
    uint256 internal constant MIN_SALE_VALUE = 0.7e18;
```

The 0.70 IMD floor (_requireWorthTheFee, line 427) is checked on the gross snapshot value. The sale that pays the auto-sell fee is the gate's net output after the hook's 0.25% PLEA burn and 1.75% IMD fee (HOOK_SALE_FEE_BPS 200), and _deliver accepts as little as 95% of that (minOut = value x 0.95 x 0.98 = 0.931 x value, line 402-403). So for a site plea at the floor the 0.35 IMD fee is more than half of the sale even with no price move, and up to 53.7% at the floor plus the allowed dip. The comment on line 425-426 ('the sale pays at least 93.1% of that') and the Letterbox test's own assertion (test/Letterbox.t.sol:408 checks 'at least about half' with a 5% tolerance) carry the right number; the constant's NatSpec does not follow from them. The money logic is correct: the fee is capped at the sale (line 412), the writer still receives the rest, no invariant-15 number is affected, and no funds are at risk. Fix: reword the NatSpec (for example 'so the fee never exceeds about 54% of a sale'); raising the floor to about 0.752 IMD (0.35 / 0.931 x 2) would make 'half' true but changes an agreed number and is the owner's decision.

**Reproduction**

Reproduced with a Foundry test on the project's fixture (test/scratch/JudgeA2.t.sol test_feeAtTheFloorExceedsHalfTheSale, fixture settings, Sepolia fee mode): bob calls letterbox.plead(amount, text) with amount = ceil(0.70 IMD / latestPrice) PLEA (worth exactly 0.70 IMD at the hourly snapshot, so TooSmallForTheFee does not fire); the panel answers 45; anyone calls deliver(id). Expected per the NatSpec: fee <= sold / 2. Actual: deliver pays the writer 0.336143532590471752 IMD and Seasons the 0.35 IMD fee, so the sale was 0.686143532590471752 IMD and the fee is 51.00% of it (5100 bps); the assertion fee * 2 > sold holds (the test passes on this tree, i.e. the NatSpec's claim fails). Note: measuring the fee as Seasons' IMD balance delta overstates it by the sale's own 0.25% prize share (0.0017 IMD); the sale is out + 0.35 IMD. With the 5% dip _deliver allows, sold can be as low as 0.6517 IMD (fee 53.7%). The fee exceeds half of the sale for every site plea worth under about 0.714 IMD at sale time.
