# PLEA Sepolia test run 4 adaptation

The imported project already implements the requested run-4 launch. This adaptation changes only reproduced defects in trader resolution and the Letterbox's appeal minimum, adds regression coverage, and updates the Letterbox creation-code commitment. No deployment or broadcast was made from this worker.

## Reproduced findings and changes

1. **Dirty upper bits in trader hook data** (`543ee2d264695da9f7ab557e8362e5fa791ba5e01cc32293e2b64e2752d18746`). On the imported code, a 32-byte word containing a wallet address plus bit 200 reverted with an empty inner hook error: both an otherwise unrestricted buy after the Cabal's death and a live buy through a router exposing `msgSender()` failed. A live buy through a router without that method also failed with the ABI decoding error instead of `RecipientRequired`. In `src/PleaHook.sol`, `_resolveTrader` now decodes a uint256 and checks that it fits uint160 before using it as an address. Invalid words continue through the existing resolution chain; their lower bits are never silently accepted as a trader. The 30,000-gas router call, plain-wallet fallback, excluded recipients, fee accounting, and buy-record rules are unchanged. `test/TraderResolution.t.sol` covers all three failures and fuzzes nonzero upper bits both before and after death, including a lower-bit address different from the router's caller.

2. **The same-share appeal clamp falls below the gate minimum** (`65e2da4c7f52bc1d2436fef8e4b43f774ddc210968162560ba4bf2d69de8b771`). Reproduced in both fee modes and both pool orientations: a site plea at floor(original balance / 100), followed by its fee sale, denial and settlement, could make `appealAuto` revert `AmountTooSmall` when the current balance was divisible by 100. The proportional floor was exactly one wei below the gate's minimum. Review reproduced a second boundary of the same defect: when both balances exceed 250M PLEA, the gate's minimum is 2.5M PLEA, but the proportional clamp reduces an original 2.5M plea below that minimum after any fee sale. All eight minimum-boundary reproduction cases failed with `AmountTooSmall` on the imported code.

   In `src/Letterbox.sol`, `_appeal` retains its existing proportional floor, then enforces the gate's existing minimum: 1% of the lesser of the current and original balances, capped at 2.5M PLEA. This preserves ordinary appeals' rounding and share bands. The minimum cannot exceed the original valid amount or the current 50% ceiling. The original amount is read once and reused, avoiding the previous duplicate `getPlea` call and keeping the fix compact. `test/AppealRounding.t.sol` covers the one-wei and capped boundaries, fuzzes balance remainders and all three entry points (`appealAuto`, `letter`, raw input), checks escrow/tip custody, and verifies unchanged rounding, need and ceilings at the 20%, 35% and 50% boundaries, in both fee modes and orientations. These comparisons first establish an hourly checkpoint so a price change does not confound the share-band assertion.

3. **Letterbox commitment** (`launch.json`). The existing creation-code hash is updated to match the changed Letterbox artifact, as expressly required by this assignment. The five entries, deployment order, constructor signatures and every other constructor argument stay as supplied. No library or dependency is added.
